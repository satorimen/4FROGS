# 4FROGS

Мобильная PWA для заказа еды-сюрприза, по PRD в [docs/PRD.md](docs/PRD.md). Жёлто-зелёный интерфейс и оригинальный маскот вдохновлены предоставленным референсом.

## Запуск

Node.js 22.12+ (проверено на 24.19), npm.

```sh
npm ci --cache /workspace/.npm-cache
npm run dev -- --port 5173
```

Production-сборка и проверка PWA:

```sh
npm run build
npm run preview -- --port 4173
npm test
```

Браузерные тесты используют системный `/usr/bin/chromium`. На другой машине задайте `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` либо установите Chromium командой `npx playwright install chromium`.

## Реализовано

- Адаптивный интерфейс, русский / английский / иврит (RTL).
- Сытное / сладкое, отдельные предпочтения и аллергии, три бюджета.
- Адрес с валидацией, геолокация по запросу с ручным вводом при отказе. Координаты не сохраняются; reverse geocoding не подключён.
- Явный демо-checkout без банковских данных и списаний.
- Демонстрационный жизненный цикл заказа с ручным продвижением статуса, отменой до принятия, раскрытием после доставки, оценкой.
- История, предпочтения и адрес в localStorage; экспорт и удаление локальных данных.
- Manifest, иконки, service worker, офлайн-оболочка. Создание заказа без сети блокируется.
- Playwright: полный сценарий, сохранение после перезагрузки, RTL, мобильный экран, отмена, offline.

## Границы демонстрации

Это клиентский прототип, **не production marketplace**. Заказы существуют только в браузере. Вход/OTP, Apple/Google Sign-In, платежи, серверная проверка зон и аллергенов, matching ресторанов, реальные курьеры, push, ресторанный и административный порталы пока не реализованы. Переданные в PRD требования к production beta не выполнены целиком.

Цена доставки в демо включена в выбранный tier; коммерческие правила остаются открытыми. Раскрываемое блюдо и ресторан вымышлены. Демо не подтверждает безопасность питания. Используйте вымышленные адреса.

## PWA

Service worker включён только в production preview/build; для установки вне localhost нужен HTTPS. После первого онлайн-открытия приложение работает офлайн. Живые процессы не сохраняются при восстановлении облачной среды. На iOS установка через «Поделиться → На экран Домой», на Android — меню браузера или кнопка в профиле. Реальная установка на устройствах iOS/Android не проверялась.

## GitHub Pages

Для размещения в `satorimen.github.io/4FROGS/`:

```sh
VITE_BASE_PATH=/4FROGS/ npm run build
VITE_BASE_PATH=/4FROGS/ npm test
```

Содержимое `dist` публикуется в корне ветки `gh-pages`, включая `.nojekyll`.
В GitHub Settings → Pages выберите Deploy from a branch → gh-pages → / (root).
Публичный адрес следует считать рабочим только после успешного deployment GitHub Pages и HTTP-проверки.
Для хостинга в корне домена запускайте обычный `npm run build` без VITE_BASE_PATH.
