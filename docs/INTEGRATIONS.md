# Переход к рабочему сервису

Провайдеры оплаты, SMS и доставки пользователем ещё не выбраны. Никакие ключи сейчас не нужны.

1. Backend: PostgreSQL, серверные users/orders/order_status_history, ограничения и аллергии отдельными полями. Перенести создание и изменение заказов из localStorage в авторизованные API; цена и переходы статуса проверяются сервером.
2. Auth: OTP-провайдер с rate limiting, сроком кода, защитой от перебора; Apple/Google OAuth через сервер. Демонстрация сейчас не имитирует успешную аутентификацию.
3. Адрес: лицензированный autocomplete/geocoding, координаты и проверка delivery zone на сервере; ручной ввод как запасной путь. Получение координат браузером само по себе не проверяет адрес.
4. Matching: проверенные часы работы, тип еды, цена, dietary и подтверждённые allergy capabilities, радиус, capacity. Отсутствие безопасного кандидата блокирует заказ. Нельзя считать UI-галочки гарантией безопасности.
5. Оплата: hosted/tokenized provider UI, authorization до matching, capture после принятия. Идемпотентные запросы, проверка подписи webhook, void/refund при неуспехе. Никогда не хранить данные карты в приложении.
6. Доставка: выбранный provider и его webhooks; SSE/polling для tracking. Статусы нельзя продвигать клиентской кнопкой в рабочем режиме.
7. Reveal: не включать сведения о ресторане/блюде в customer API до DELIVERED (скрытие только в интерфейсе недостаточно).
8. Порталы: ресторан принимает/отклоняет/готовит заказ, admin действует через RBAC и audit logs. Отдельные требования — в PRD.
9. Push и operations: уведомления по согласию, аллергические инциденты и поддержка, юридические документы, удаление данных.
10. Перед beta: реальные partner agreements, зоны, экономика tiers/доставки, политика отмен, нагрузка, безопасность, доступность, тесты устройств и пилот с ресторанами.

Нынешняя граница данных: `src/model.ts` содержит локальную модель и проверку сохранённых данных; `src/main.tsx` — действия демонстрации. Тексты находятся в `src/i18n.ts`. Подмена методов API должна сопровождаться серверными гарантиями, а не только заменой UI-кнопок.
